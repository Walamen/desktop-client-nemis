# Phase 3.5 Design: Pre-Sync Hardening

**Date:** 2026-07-16
**Status:** Approved
**Branch:** `phase-3.5-pre-sync-hardening` (off `main`, tip `32f9a4a`)

## Goal

Close every architectural debt item that blocks Phase 4 (Synchronization):
renderer settings allowlist, atomic sync-batch claiming, chunked IN-updates,
a complete RepositoryError → IPC error-mapping layer, SQLCipher adoption,
an IPC-boundary audit, an error-wrapping audit, and a final architecture
review with a Phase-4 readiness report.

**Out of scope:** synchronization features, API communication, authentication
logic, UI features, business entities. No shortcuts; all implementations
extend the existing architecture.

## Decisions (settled during brainstorming)

1. **SQLCipher: implement now.** `better-sqlite3-multiple-ciphers@12.11.1`
   (SQLCipher-capable fork of exactly our better-sqlite3 version) ships
   prebuilds for both ABIs this machine needs — `electron-v146` and
   `node-v137` win32-x64 — so the no-toolchain constraint does not block it.
   Adopted via pnpm alias so imports, `@types/better-sqlite3`, rebuild
   scripts, and packaging hooks stay unchanged.
2. **Key management: safeStorage-wrapped key.** Random 256-bit key generated
   on first run, wrapped with Electron `safeStorage` (Windows DPAPI,
   per-OS-user), stored in userData. No user interaction; never plaintext at
   rest; fail hard (typed error) if safeStorage is unavailable — never fall
   back to an unencrypted database.
3. **Error-code contract is a closed union** owned by `packages/types`; one
   mapper module in the main process is the single source of truth for every
   present and future endpoint.

## Task 1 — Settings allowlist

- New `apps/desktop/electron/security/settingsAllowlist.ts`:
  - `RENDERER_READABLE_SETTINGS: ReadonlySet<string>` — initially
    `'theme'`, `'language'`. Extending = adding one string here.
  - `assertRendererReadableSetting(key: string): void` — throws
    `ForbiddenError` for any key not in the set.
- New `ForbiddenError` in `packages/shared/src/errors.ts`: an
  `ApplicationError` subclass with code `FORBIDDEN` — application-level
  error, no internal exception details.
- The `settings:get` handler validation becomes: shape check
  (`assertSettingKeyArg`) → allowlist check → `AppSettingsService.get`.
  Permission logic lives only in the allowlist module.
- Flow: Renderer → IPC → allowlist validation → SettingsService →
  Repository. Sensitive settings never become renderer-accessible merely by
  existing in the database.
- Tests: allowed key passes; disallowed key rejected with `FORBIDDEN`
  payload (never the value); allowlist module unit-tested.

## Task 2 — Atomic batch claiming

- New `claimBatch(limit: number): SyncQueueItem[]` on
  `ISyncQueueRepository` + `SqliteSyncQueueRepository`, exposed through
  `SyncQueueService.claim(limit)`.
- Implementation: ONE IMMEDIATE transaction — select oldest pending ids
  (`status='pending'`, `ORDER BY createdAt, id`, `LIMIT`), mark exactly
  those ids `in_flight` (via the Task 3 chunked update), return the claimed
  items. Empty queue → `[]` without writes.
- `nextBatch` remains as a read-only preview; `claimBatch` is documented as
  the sync-worker API.
- **Race-safety argument (recorded in docs):** (a) today there is exactly
  one connection in one synchronous process — better-sqlite3 runs the whole
  transaction callback without yielding, so interleaving is impossible;
  (b) for any future second worker/connection, IMMEDIATE acquires SQLite's
  write lock BEFORE the select, so a competing claimer cannot read-then-mark
  between our find and our mark — it blocks until commit and then observes
  the rows as `in_flight`. No other worker can ever observe the claimed
  records as pending mid-operation.
- Tests: claim marks and returns in creation order; claimed items excluded
  from a subsequent claim; empty result; rollback restores pending on
  mid-claim failure.

## Task 3 — Chunked IN-updates

- New `apps/desktop/electron/data/queries/chunk.ts`:
  - `DEFAULT_PARAMETER_CHUNK_SIZE = 900` (safe under SQLite's legacy
    999-variable floor; configurable per call).
  - `chunkArray<T>(items: readonly T[], size: number): T[][]`.
- New protected `BaseRepository.updateByIds(ids, changes, chunkSize?)`:
  chunks the id list, executes every chunk inside ONE IMMEDIATE transaction
  (a failing chunk rolls back all — transaction behavior preserved), returns
  summed `changes`.
- `SqliteSyncQueueRepository.#setStatus` (the only `WHERE id IN (...)`
  update today) and Task 2's `claimBatch` both use it. No repository ever
  encodes the parameter limit; no duplicated chunking logic.
- Tests: chunk boundary behavior (0, 1, exactly chunk-size, chunk-size+1
  ids); atomicity across chunks (fault injection); `chunkArray` unit tests.

## Task 4 — RepositoryError → IPC error mapping

- `packages/types/src/ipc.ts`:
  - `IpcErrorCode` closed union: `VALIDATION_FAILED | DUPLICATE | NOT_FOUND
    | CONFLICT | UNAUTHORIZED | FORBIDDEN | DATABASE_UNAVAILABLE |
    MIGRATION_REQUIRED | IPC_ERROR | UNEXPECTED_ERROR`.
  - `IpcErrorPayload` becomes `{ code: IpcErrorCode; message: string;
    issues?: { field: string; message: string }[] }` — `issues` carries our
    own validator strings so forms can render per-field errors.
- New `apps/desktop/electron/ipc/errorMapping.ts` — `toIpcError(error):
  IpcErrorPayload`, the single source of truth, called from the registrar's
  catch for EVERY endpoint (current and future CRUD endpoints reuse it
  without modification):
  - `RepositoryError` by code: `REPO_VALIDATION` → `VALIDATION_FAILED`
    (+ issues), `REPO_DUPLICATE` → `DUPLICATE`, `REPO_NOT_FOUND` →
    `NOT_FOUND`, `REPO_TRANSACTION` → `CONFLICT`, `REPO_QUERY` /
    `REPO_UNKNOWN` → `UNEXPECTED_ERROR`.
  - `DatabaseError` by code: `DB_CONNECTION` → `DATABASE_UNAVAILABLE`,
    `DB_MIGRATION` → `MIGRATION_REQUIRED`, all others →
    `UNEXPECTED_ERROR`.
  - `ApplicationError` subclasses keep their codes narrowed into the union
    (`FORBIDDEN`, `IPC_ERROR`, `CONFIGURATION_ERROR` → `UNEXPECTED_ERROR`).
  - `UNAUTHORIZED` is defined-and-reserved for Phase 4 authentication.
  - Anything unrecognized → `UNEXPECTED_ERROR`.
- Messages are fixed, per-code generic strings (except validator-issue
  text, which we author). Raw SQLite driver errors can never reach the
  renderer: they are already `RepositoryError`/`DatabaseError` by the time
  they cross layers, and the mapper masks everything else.
- `packages/shared` `toIpcErrorPayload` is subsumed: the registrar switches
  to `toIpcError`; shared keeps `ApplicationError`/`IPCError`/
  `ForbiddenError` definitions.
- Tests: one table-driven mapping test covering every taxonomy code and the
  masking default; registrar-level test that a thrown `ValidationError`
  reaches the payload with `issues` and code `VALIDATION_FAILED`.

## Task 5 — SQLCipher

- **Dependency:** `apps/desktop/package.json` —
  `"better-sqlite3": "npm:better-sqlite3-multiple-ciphers@^12.11.1"`.
  `@types/better-sqlite3` unchanged. Root `rebuild:node`/`rebuild:electron`
  scripts unchanged (they cd into `node_modules/better-sqlite3`, whose
  installed package.json now names the fork — prebuild-install downloads
  the fork's binaries for the same ABIs). `forge.config.ts`
  `packageAfterCopy` unchanged (copies the same folder path). Check
  `pnpm-workspace.yaml` `onlyBuiltDependencies` for a needed alias entry.
- **Cipher scheme:** `cipher='sqlcipher'` (SQLCipher-4 compatible — honors
  CLAUDE.md "SQLCipher (preferred)" and standard tooling). Accepted ~5–15%
  page-I/O overhead, documented.
- **Key management:** new `apps/desktop/electron/security/databaseKey.ts` —
  `loadOrCreateDatabaseKey(userDataDir): string` (64-char hex):
  - First run: `crypto.randomBytes(32)` → hex →
    `safeStorage.encryptString` → write wrapped blob to
    `<userData>/nemis-db-key.bin`.
  - Later runs: read blob → `safeStorage.decryptString` → hex key.
  - `safeStorage.isEncryptionAvailable()` false, or blob corrupt → throw a
    typed error (surfaced by main.ts's existing fatal-startup dialog).
    Never fall back to plaintext.
  - Called from `main.ts` AFTER `whenReady` (safeStorage requirement),
    passed into `DatabaseManager` options.
- **Database layer:** `Database.open` gains optional
  `encryptionKey?: string` (hex). Sequence when provided:
  1. If the file exists and its header starts with `SQLite format 3\0`
     (plaintext — all current dev databases), open keyless and encrypt in
     place via `PRAGMA rekey` (one-time migration, audit-logged by the
     manager).
  2. Otherwise apply `PRAGMA cipher='sqlcipher'` + key pragma BEFORE any
     other pragma/read, then verify with a read; wrong/missing key →
     `IntegrityError`.
  - Keyless open (no `encryptionKey`) keeps working — the existing unit
    suite runs unencrypted; encryption-specific tests supply keys.
- **DatabaseManager:** accepts and forwards `encryptionKey`; audit-logs the
  one-time plaintext→encrypted migration event.
- **Tests:** encrypted round-trip (write, close, reopen with key); wrong
  key → `IntegrityError`; keyless open of an encrypted file fails;
  plaintext→encrypted in-place migration preserves data; existing suite
  green unmodified.
- **Proof:** packaged-app smoke test (Phase 2 lesson — packaging bugs are
  invisible to unit tests): `pnpm make`, launch the packaged exe, verify
  the database file header is NOT `SQLite format 3` (encrypted), clean
  shutdown, relaunch reopens successfully.

## Task 6 — IPC-boundary audit

- Audit both existing endpoints (`system:get-version`, `settings:get`)
  against: input validation (arity + shape), unexpected-value rejection,
  typed contracts (`IpcContract`), authorization where appropriate (the
  allowlist is settings' authorization), no renderer trust, no repository
  implementation exposure, sanitized payloads only.
- Fix any findings; record the "adding an IPC endpoint" checklist —
  contract entry → `IpcChannels` constant (exhaustiveness-checked) → shape
  validator → authorization check where applicable → thin handler →
  `toIpcError` mapping → preload method — in `docs/conventions.md`.

## Task 7 — Error-wrapping audit

- Systematic sweep of `apps/desktop/electron/database/` for raw
  `.prepare(` / `.exec(` / `.pragma(` calls outside taxonomy wraps. Known
  suspects: `DatabaseManager.#writeAudit`, `BackupService`,
  `DatabaseHealthService`, `Database.open` internals; anything new from
  Task 5.
- Every database failure becomes `DatabaseError` inside the platform layer;
  `RepositoryError` at the data-layer boundary (already enforced);
  a mapped `IpcErrorPayload` at IPC (Task 4). This three-layer boundary is
  stated explicitly in the report — the platform's internal taxonomy is
  `DatabaseError` BY DESIGN; "no raw SQLite driver errors escape" is the
  invariant at every layer.
- Fix violations with closed-DB (or fault-injection) tests proving each
  wrap site.

## Task 8 — Architecture review + report

- Final whole-branch review (most capable model) confirming: repository
  boundaries intact; services thin; IPC handlers thin; validation
  centralized; transactions correct; error handling consistent across all
  three layers; claiming race-condition safe; renderer cannot access
  privileged data; SQLCipher finalized; no remaining Phase-4-blocking debt.
- `docs/phase-3.5-report-2026-07-16.md`: files changed, architectural
  decisions, remaining risks, recommended improvements, explicit Phase 4
  readiness confirmation.
- Documentation updates: `docs/data-access.md` (claimBatch + chunking +
  error mapping), `docs/database.md` (encryption, key management, cipher
  scheme, migration), `docs/conventions.md` (IPC endpoint checklist).

## Acceptance criteria

- All eight tasks implemented/verified as specified.
- Full gate green: `pnpm test` (existing + new tests), `pnpm typecheck`,
  `pnpm lint`, `pnpm format:check`, `pnpm make`.
- Packaged-app smoke test proves the shipped database is encrypted and the
  app runs a full start→shutdown→restart cycle.
- Final review verdict: ready for Phase 4.

## Known deferrals / flags

- `UNAUTHORIZED` mapping has no producer until Phase 4 authentication.
- Renderer-side typed error consumption (parsing `IpcErrorPayload.issues`
  in forms) arrives with the first form UI, not this phase.
- DataLayer-recreation-after-restore constraint unchanged (documented in
  Phase 3); still no restore flow wired.
- Preload currently flattens errors to `Error("[code] message")` — carrying
  the structured payload to renderer callers becomes relevant with the
  first write endpoint; the payload shape this phase defines is what it
  will carry.
