## Work Items

### A. Security & lifecycle hardening

1. **CSP tightening** (`electron/security/csp.ts`): add `base-uri 'none'`, `object-src 'none'`, `form-action 'self'`, `frame-ancestors 'none'` to the production CSP. `default-src` does not cover these directives; with `'unsafe-inline'` scripts unavoidable, a stray `<base>` tag would widen injection impact.
2. **`app://` handler** (`electron/main/appProtocol.ts`): reject requests whose URL host is not `renderer` (403) and whose method is not GET/HEAD (405). Both logged.
3. **Permission handling** (new `electron/security/permissions.ts`): `session.setPermissionRequestHandler` denying all permission requests by default, each denial logged with the permission name. Phase 2 features opt in explicitly.
4. **Crash/rejection safety nets** (`electron/main/main.ts` + `electron/services/logger.ts` area):
   - `.catch` on the `whenReady` chain → log fatal, `app.quit()`.
   - `process.on('uncaughtException')` → log, `dialog.showErrorBox` with a plain-language message, `process.exit(1)`.
   - `process.on('unhandledRejection')` → log error (no dialog; non-fatal).
5. **Single-instance lock** (`electron/main/main.ts`): `app.requestSingleInstanceLock()`; if not obtained, quit immediately; on `second-instance`, restore + focus the existing window.
6. **Build debt removal** (`forge.config.ts`, `package.json`, new `scripts/fix-squirrel-7z.mjs`):
   - Register the already-installed `@electron-forge/plugin-auto-unpack-natives` in the Forge plugins array.
   - `scripts/fix-squirrel-7z.mjs`: idempotent Node script that copies `node_modules/electron-winstaller/vendor/7z-x64.{exe,dll}` to `7z.{exe,dll}` if missing; wired into the app's `make` script before `electron-forge make`. Update `docs/architecture.md` build notes to reflect automation.

### B. IPC scalability refactor (behavior-preserving)

Problem: the registrar's `handle()` supports only zero-argument handlers; preload wires each method by hand with a locally-chosen generic. This does not scale to hundreds of endpoints and lets the two sides drift.

Design: a **typed contract map** in `@nemis-desktop/types`:

```ts
export interface IpcContract {
  [IpcChannels.SYSTEM_GET_VERSION]: { args: []; result: string };
}
```

- Main (`electron/ipc/registrar.ts`): `handle<C extends IpcChannel>(channel: C, validate, handler: (...args: IpcContract[C]['args']) => IpcContract[C]['result'] | Promise<...>)` — validator remains mandatory and runs before the handler; every response is still an `IpcResult<T>` with `toIpcErrorPayload` masking. Handlers organized per domain module (`electron/ipc/handlers/system.ts`) registered from a single `registerIpcHandlers()`.
- Preload (`electron/preload/preload.ts`): `invoke<C extends IpcChannel>(channel: C, ...args: IpcContract[C]['args']): Promise<IpcContract[C]['result']>` — same unwrap/throw behavior (`[CODE] message`).
- Channel naming convention `domain:action` documented in conventions doc.
- `system:get-version` behavior is byte-identical on the wire.

### C. Testability extractions + Vitest harness

Extract pure logic from Electron-bound modules (thin wrappers keep identical behavior):

- `electron/security/hardenWindow.ts`: export existing pure `isAllowedNavigation(url, allowedOrigins)`.
- `electron/main/appProtocol.ts`: extract `resolveRendererPath(rendererRoot, pathname): string | null` (null = traversal violation) into `electron/main/rendererPath.ts` (pure, node:path only).
- `electron/config/env.ts`: extract `parseConfig(env: NodeJS.ProcessEnv, isDev: boolean): AppConfig` (pure; throws `ConfigurationError`); `loadConfig` keeps dotenv + `app.isPackaged` + caching and delegates.

**Vitest** (devDependency at workspace root; single root `vitest.config.ts` covering `packages/**` and `apps/desktop/electron/**` pure modules):

- `toIpcErrorPayload`: ApplicationError passthrough, subclass codes, unknown-error masking.
- `isAllowedNavigation`: allowed dev origin, evil origin, userinfo-bypass URL, port-collision prefix, custom-scheme (`app://renderer/` allowed, other custom schemes rejected), malformed URL.
- `resolveRendererPath`: `/` → index.html, nested route with trailing slash, `_next` asset path, encoded `..` traversal, backslash traversal, sibling-prefix directory (`out-evil`), root itself.
- `parseConfig`: defaults (dev→debug, prod→info), NEMIS_LOG_LEVEL override, invalid level throws ConfigurationError, rendererDevUrl override.

~20 tests total. `pnpm test` added to root scripts and the quality gate. No renderer/component tests (no logic there yet).

### E. Quality gate (all must pass before the report is written)

1. `pnpm install`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm test` — exit 0.
2. `pnpm --filter @nemis-desktop/app build:renderer`, `package`, `make` (7z fix automated) — artifacts produced.
3. Dev-mode CDP verification: node isolation, `window.nemis` present, version renders, popup denied, disallowed navigation blocked (evil + userinfo URLs), permission request denied and logged.
4. Packaged-app CDP verification: `app://renderer/` origin, version renders, Tailwind styles active.
5. One-off `npx knip` scan for unused dependencies/exports/files; genuine findings fixed, false positives documented in the report.
